# Редакции и лицензирование MGate

Документ для операторов: чем отличаются редакции, как перейти на Pro, **какие данные при этом
уходят вендору и какие — никогда**, что происходит без связи с сервером лицензий и как
переносить установку. Механизм лицензирования целиком находится внутри закрытого бэкенда
(образ `ghcr.io/mgate-server/mgate`), поэтому здесь он описан как «чёрный ящик»: наблюдаемое
поведение, сроки, передаваемые данные и сетевые требования. Внутреннее устройство механизма и
формат обмена с сервером лицензий не публикуются. Обоснование решений — ADR
[0007](adr/0007-editions-and-licensing-model.md), [0008](adr/0008-license-transport-crypto.md),
[0014](adr/0014-license-choice.md), [0015](adr/0015-degraded-mode-policy.md).

> Значения таймеров и лимитов ниже — действующие значения по умолчанию. Если в новой версии они
> меняются, это отражается в этом документе и в [`CHANGELOG.md`](../CHANGELOG.md).

## 1. Коротко

- **Community** бесплатна навсегда: полноценный почтовый сервер на **1 домен**. Без активации
  Community **не обращается** к серверам вендора.
- **Pro** — годовая подписка: без ограничения числа доменов (или с лимитом тарифа) и
  дополнительные Pro-модули (часть модулей ещё в разработке — см. §2.2). Подтверждается коротким подписанным «лизом», который установка
  продлевает онлайн раз в час.
- Без связи с сервером лицензий Pro работает **72 часа (3 дня)**, затем установка переходит к
  правам Community; ещё через **7 дней** домены сверх лимита временно приостанавливаются
  (входящая почта получает `450 4.7.1`, IMAP продолжает работать). **Основной домен не
  затрагивается никогда.**
- Содержимое писем, адреса и списки пользователей **никогда** не передаются.

| Очередь, live-логи, статистика, автовыпуск Let's Encrypt/ZeroSSL и загрузка собственных сертификатов | да | да |

| Связь с сервером лицензий | не требуется | раз в час (продление лиза) |

### 2.2. Pro-модули: что работает сегодня

| Модуль | Состояние | Что это даёт |
|---|---|---|
| Неограниченное число доменов (`pro.unlimited_domains`) | работает | снимает лимит Community в 1 домен (или задаёт лимит тарифа) |
| White-label брендинг (`pro.branding`) | работает | название продукта и логотип в шапке интерфейса и в заголовке вкладки; favicon, акцентный цвет, ссылка поддержки и текст футера сохраняются, но пока не отображаются |
| DMARC Intelligence (`pro.dmarc_intelligence`) | работает | полные IP-адреса источников (в Community они маскируются), история до 90 дней (в Community — 7), скачивание исходных XML-отчётов. Отчёты загружаются в виде XML вручную — автоматического приёма нет; имена хостов и география источников не определяются |
| Backup Center (`pro.backup_center`) | в разработке | API отвечает `501 not_implemented`; резервное копирование — [`BACKUP.md`](BACKUP.md) (restic, входит в Community) |
| Advanced Dashboard (`pro.advanced_dashboard`) | в разработке | API отвечает `501 not_implemented` |
| Multi-tenant RBAC (`pro.multi_tenant_rbac`) | в разработке | расширенная мультиарендность поверх базовых Domain Admin и квот (они входят в Community); API отвечает `501 not_implemented` |
| DNS-Автопилот, фоновая сверка записей (`pro.dns_autopilot`) | в разработке | API отвечает `501 not_implemented`. Ручная автонастройка DNS из мастера домена (Cloudflare, Selectel) работает; в интерфейсе она показана как Pro-функция |
| Приоритетные обновления (`pro.priority_updates`) | в разработке | API отвечает `501 not_implemented` |

Модули «в разработке» присутствуют в интерфейсе с пометкой «В разработке» и не выдают
вымышленных данных: пока модуль не реализован, он отвечает `501` независимо от редакции.

Лимит Community и состав Pro-модулей могут уточняться в новых версиях; всё, что входит в
Community сегодня, не будет убрано из неё задним числом ради Pro.

### 2.1. Один образ, а не две сборки

Существует **ровно один** образ бэкенда — `${MGATE_REGISTRY}/mgate` (по умолчанию
`ghcr.io/mgate-server/mgate`), тот же самый, что используется в `docker-compose.yml`. В нём
Pro-модули присутствуют физически всегда; без действительного лиза Pro-функции API отклоняет
(ответ `403`), фоновые задачи Pro не запускаются, данные Pro-модулей не создаются — включение
происходит исключительно проверкой лицензии во время работы. Нет отдельной «сборки из
исходников», которая давала бы Community-only бинарник: исходный код этого образа нигде не
публикуется, поэтому собрать его самостоятельно невозможно в принципе — не только для
Pro-модулей, но и вообще.

## 3. Что входит в Community

Community — не «пробная версия», а полноценный почтовый сервер: все протоколы и порты, антиспам
и антивирус, DKIM-подпись и автогенерация DNS-записей, выпуск сертификатов, админка, webmail,
личный кабинет, резервное копирование. Ограничение одно — число доменов (ровно один, основной).
Число ящиков, алиасов и объём почты в Community не ограничены лицензией (только ресурсами
сервера).

## 4. Как перейти на Pro

Перед активацией в установке должен быть создан хотя бы один домен: первый созданный домен
становится **основным**, и слот Pro привязывается к нему.

### 4.1. По ссылке (рекомендуется)

1. Админка → «Лицензия» → «Перейти на Pro».
2. Установка запрашивает у сервера лицензий одноразовую ссылку оплаты, привязанную именно к
   этой установке, и открывает страницу кабинета вендора.
3. В кабинете вы видите данные установки (имя хоста, основной домен, IP) — убедитесь, что это
   ваш сервер, — затем оплачиваете подписку или назначаете уже купленный свободный слот.
4. После оплаты кабинет возвращает вас в админку, и установка сразу получает лиз. Страницу
   можно закрыть раньше: фоновый процесс сам завершит активацию, пока ссылка действительна
   (ориентир — 60 минут).

### 4.2. По коду

1. Купите подписку в кабинете и получите одноразовый код вида `MGT-XXXXX-XXXXX-XXXXX-XXXXX`.
2. Админка → «Лицензия» → «Ввести код», либо в консоли:
   ```sh
   docker compose exec api mgate license activate-code MGT-XXXXX-XXXXX-XXXXX-XXXXX
   ```
3. Код одноразовый: после активации он «сгорает», повторный ввод на любой установке вернёт
   «код уже использован». Регистр и дефисы при вводе не важны.
4. Неиспользованный код можно отозвать в кабинете. Считайте код секретом, пока он не использован:
   кто первым его введёт, тот и займёт слот (слот можно освободить в кабинете).

### 4.3. Проверка состояния

```sh
docker compose exec api mgate license status
```

Показывает идентификатор установки, состояние (`Community`, `ProActive`, `ProOffline`,
`CommunityDegraded`, `ProConflict`), идентификатор лиза и срок его действия.

## 5. Какие данные передаются вендору

Обмен идёт только с `https://cloud.mgate.example` и только по HTTPS. Соединения всегда инициирует
установка; сервер лицензий к установке не подключается.

> **Адрес сервера лицензий.** Community работает без сервера лицензий. Адрес зафиксирован в
> коде backend и не настраивается через `.env`, TOML или Helm. Сейчас в сборке используется
> плейсхолдер `https://cloud.mgate.example`; рабочий адрес поставляется в сборке вендора.
> Пока используется плейсхолдер, попытки активации завершаются сетевой ошибкой — это ожидаемо
> и не влияет на работу Community.

### 5.1. Когда происходит обмен

| Ситуация | Запросы к серверу лицензий |
|----------|----------------------------|
| Community без активации | **никаких** (нет телеметрии, нет «пингов», нет проверки обновлений через этот канал) |
| Активация по ссылке | запрос ссылки, затем опрос статуса раз в несколько секунд до завершения |
| Активация кодом | один запрос |
| Pro | продление лиза раз в час; кроме того, редкие служебные запросы к тому же серверу |
| «Освободить лицензию» | один запрос |

### 5.2. Что передаётся

| Данные | Когда | Зачем |
|--------|-------|-------|
| Публичный ключ установки и её идентификатор | всегда | идентификация установки, привязка лиза |
| Случайный идентификатор (UUID), созданный при установке | активация, продление | различение копий установки |
| Имя хоста (`MGATE_HOSTNAME`) | активация, продление | отображение в кабинете, проверка ссылки возврата |
| Основной домен | активация, продление | привязка слота |
| Системный идентификатор кластера PostgreSQL (создаётся при инициализации кластера) | активация, продление | обнаружение клонов и восстановлений |
| Версия MGate, ОС/архитектура | активация, продление | совместимость и поддержка |
| **Число** доменов и **число** ящиков | продление | контроль тарифного лимита |
| E-mail администратора | только активация по ссылке | вход в кабинет / связь с аккаунтом |
| IP-адрес, с которого пришёл запрос | виден серверу при любом запросе | отображение в кабинете, IP-ограничения, защита от злоупотреблений |

### 5.3. Что не передаётся никогда

- содержимое писем, заголовки, вложения, метаданные доставки;
- адреса ящиков, алиасы, списки пользователей, контакты;
- имена доменов, кроме основного;
- пароли, ключи DKIM, сертификаты, `MGATE_SECRET_KEY`, приватный ключ установки;
- журналы (логи), IP-адреса ваших пользователей, статистика трафика.

Клиент лицензирования — часть закрытого бэкенда, его исходный код не публикуется, поэтому этот
список нельзя проверить чтением кода. Он подкреплён договорно: [`EULA.md`](../EULA.md)
(раздел 6) содержит сводку того же перечня как обязательство вендора. Сетевое поведение можно
наблюдать снаружи: `worker` и `api` обращаются к вендору только по HTTPS и только к одному
хосту — `https://cloud.mgate.example`; других обращений к серверам вендора установка не делает
(см. §5.4).

### 5.4. Сетевые требования

Для Pro нужен исходящий HTTPS (TCP 443) из контейнера `worker` (и `api` — для активации) к
`https://cloud.mgate.example`. Входящих соединений от сервера лицензий нет — открывать для него порты
не нужно. Поддерживаются `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`: задайте их в `.env` — compose
передаёт эти переменные сервисам `api` и `worker` (подробнее — [`CONFIGURATION.md`](CONFIGURATION.md)),
в том числе корпоративные прокси с подменой сертификата (после добавления их CA в доверенные). Системное время сервера должно быть
синхронизировано (NTP) — это нужно и для лицензии, и для почты (TLS, DKIM, TOTP).

## 6. Работа без связи с сервером лицензий

| Время с последнего успешного продления | Состояние | Что происходит |
|---------------------------------------|-----------|----------------|
| до 2 ч | `ProActive` / `ProOffline` | ничего заметного: единичные сбои продления не показываются |
| 2 ч – 72 ч | `ProOffline` | всё работает как Pro; в админке предупреждение; установка повторяет попытки |
| 72 ч – 72 ч + 7 дней (≈ 10 дней) | `CommunityDegraded` (отсрочка) | права Community: Pro-модули выключены (их данные сохраняются), новые домены сверх лимита (1) создать нельзя; **все домены продолжают принимать и отправлять почту**; в админке — дата предстоящей приостановки |
| после ≈ 10 дней | `CommunityDegraded` (ограничения) | домены сверх лимита получают статус `suspended_license` |

Что значит `suspended_license`:

- **входящая почта** на эти домены получает временный отказ `450 4.7.1` — отправляющие серверы
  повторяют доставку, письма не теряются сразу;
- **отправка** с адресов этих доменов (почтовые клиенты, webmail) временно отклоняется;
- **IMAP/POP3 и webmail для чтения работают** — пользователи сохраняют доступ к своей почте и
  могут её выгрузить;
- настройки, DNS-записи, ключи DKIM, сертификаты не удаляются;
- **основной домен не приостанавливается никогда**; при лимите Community в 1 домен это на
  практике означает, что все остальные домены установки приостанавливаются, а основной
  продолжает работать без изменений. Выключив или удалив ненужный домен, вы можете сами
  выбрать, какой домен останется основным.

Важно: отправляющие серверы держат письмо в очереди ограниченное время (типично — до 5 дней),
после чего возвращают отправителю отказ. Приостановка дольше нескольких дней фактически означает
потерю входящих писем для этих доменов — не допускайте её, восстанавливая связь или
лицензию.

Как только установка снова получает действительный лиз, все приостановленные домены
возвращаются в работу **автоматически и немедленно**.

Подписка, закончившаяся без продления, ведёт себя так же: текущий лиз действует до своего
срока (до 72 часов), затем — отсрочка 7 дней и приостановка лишних доменов. Продление
подписки в кабинете возвращает Pro при следующем продлении лиза (в течение часа).

Работа полностью без интернета (air-gapped) для Pro в текущей версии не поддерживается.

## 7. Перенос на новый сервер

Слот Pro одновременно принадлежит одной установке. Варианты переноса:

1. **Старый сервер доступен:** админка старого сервера → «Лицензия» → «Освободить лицензию»
   (или `mgate license deactivate`). Старый сервер сразу переходит в Community, слот свободен.
   На новом сервере — обычная активация по ссылке (выбрать свободный слот) или новым кодом.
2. **Старый сервер недоступен:** кабинет → «Установки» → «Освободить слот». Если старый сервер
   позже появится в сети, он получит отказ и перейдёт в Community.
3. **Перенос восстановлением бэкапа** (та же установка на новом железе): допускается без
   действий в кабинете, **если старый сервер выключен**. Если обе копии будут работать
   одновременно, это распознается как клон (раздел 9).

Кабинет показывает все установки аккаунта: имя хоста, основной домен, IP, время последней связи.

## 8. Резервные копии и восстановление

Ключ установки и состояние лицензии хранятся в БД и входят в резервную копию — после
восстановления установка остаётся той же и продолжает работать с лицензией. Восстановление
старой копии (откат после неудачного обновления, откат снапшота ВМ) сервер лицензий распознаёт
и допускает автоматически. Если восстановленную копию всё же сочтут клоном, достаточно
подтвердить в кабинете «это была одна установка».

## 9. Конфликт клонов

Если две работающие копии используют одну и ту же идентичность (клонированная ВМ,
скопированные тома, восстановленный бэкап при работающем оригинале), сервер лицензий
замораживает слот, и **обе** копии переходят в `ProConflict` с правами Community.
Почта при этом продолжает работать, а до приостановки лишних доменов остаётся 7 дней.

Как решить:

1. В админке той копии, которую вы хотите оставить, нажмите «Это основная установка —
   перевыпустить идентичность». Установка создаст новый ключ и откроет страницу кабинета.
2. В кабинете подтвердите, что слот передаётся этой установке (сверьте hostname, домен, IP).
3. Выбранная копия вернётся в Pro, остальные копии будут отключены от Pro окончательно.
4. Если это было ложное срабатывание (одна установка), в кабинете можно нажать «Это была одна
   установка» — заморозка снимется.

Ключ установки хранится зашифрованным `MGATE_SECRET_KEY`: при клонировании сервера меняйте
его только осознанно (без него установка не сможет расшифровать свой ключ и потребует новой
активации).

## 10. Привязка к IP

Сервер лицензий видит IP, с которого установка выходит в интернет, и показывает его в кабинете.
Дополнительно:

- **владелец аккаунта** может ограничить слот списком IP/подсетей (CIDR) — запросы с других
  адресов сервер лицензий отклонит; это защищает слот, если ключ установки украдут.
  Не включайте ограничение, если исходящий IP сервера меняется (динамический NAT, несколько
  провайдеров, IPv6 privacy addresses) — или указывайте подсеть целиком;
- **вендор** может блокировать IP-адреса и сети, с которых идут злоупотребления.

При отказе по IP текущий лиз продолжает действовать до своего срока, в админке — предупреждение
с причиной отказа.

## 11. Смена основного домена и имени хоста

Слот привязан к основному домену. Сменить основной домен можно, но это требует подтверждения в
кабинете, иначе сервер лицензий отклонит продление (в админке будет показана причина), и Pro
доработает только до конца срока текущего лиза. Смена `MGATE_HOSTNAME` подтверждения не требует
и просто отображается в кабинете.

## 12. FAQ

**Сколько бесплатных установок можно запустить?**
Сколько угодно. Каждая Community-установка ограничена 1 доменом; объединять их в единую
систему лицензия не мешает, но и централизованного управления между ними нет. Это осознанная
часть модели: «поднять почтовый сервер бесплатно» — базовое обещание проекта.

**Что будет с почтой, если вендор перестанет существовать или сервер лицензий будет недоступен?**
Pro перестанет продлеваться; установка продолжит работать как Community, основной домен — без
ограничений. Остальные домены будут приостановлены примерно через 10 дней (72 часа до
истечения лиза + 7 дней отсрочки); вы можете перенести их на другие Community-установки.
Офлайн-лицензии и отдельная политика на случай прекращения деятельности вендора в текущей
версии не предусмотрены.

**Может ли вендор удалённо отключить мою почту?**
Нет. Сервер лицензий может только не продлить или отозвать Pro. Что происходит с доменами,
решает локальная, публичная и проверяемая политика (раздел 6) с отсрочкой; основной домен и
лимит Community не затрагиваются никогда.

**Можно ли собрать бэкенд из исходников и активировать в нём Pro?**
Нет: исходный код бэкенда не публикуется вообще — его физически негде взять для
самостоятельной сборки. Единственный способ запустить MGate — использовать опубликованный образ
`${MGATE_REGISTRY}/mgate` (по умолчанию `ghcr.io/mgate-server/mgate`), в котором Pro-модули
уже есть и включаются лицензией. Часть проекта, публикуемая исходным кодом, — deploy kit,
конфигурация почтового стека и SPA — здесь собирается из исходников как обычно (в рамках прав,
описанных в [`EULA.md`](../EULA.md); лицензия с открытым исходным кодом на неё не
предоставляется, см. [`LICENSE`](../LICENSE)).

**Установка не видит интернет через прокси.**
Задайте `HTTPS_PROXY` (и при необходимости `HTTP_PROXY`, `NO_PROXY`) в `.env`: compose передаёт
их сервисам `api` и `worker`, а `make init` не удаляет такие переменные при повторном запуске.
После изменения `.env` выполните `docker compose up -d`. При прокси с подменой сертификата
добавьте его CA в доверенные.

**«Часы сервера отстают» — что это?**
Если системные часы сервера заметно отстают от реального времени, лиз считается
недействительным до исправления времени. Настройте NTP на хосте.

**Я восстановил бэкап, и Pro пропал.**
Скорее всего, в бэкапе был старый лиз, и он ещё не продлился. Проверьте `mgate license status`
и доступ к серверу лицензий; продление происходит автоматически. Если показан конфликт клонов —
см. раздел 9.

**Можно ли перенести код активации на другую установку?**
Нет, код одноразовый. Переносится слот: освободите его (раздел 7) и активируйте новую
установку по ссылке, выбрав свободный слот.

**Сколько стоит Pro?**
Условия подписки публикуются на сайте проекта; этот документ их не содержит.

## 13. Честно о защите

Мы считаем важным не вводить операторов в заблуждение:

- **Исходный код бэкенда не публикуется вообще.** Закрытый бинарник — единственная форма, в
  которой распространяется бэкенд, поэтому форкать с вырезанием проверки нечего. Исходным
  кодом публикуются только deploy kit, конфигурация почтового стека и SPA (без лицензии на
  форк или распространение изменённой версии, см. [`LICENSE`](../LICENSE)) — ни один из них
  не содержит проверки лицензии.
- **Это не делает бинарник неприступным.** Скомпилированный код всё ещё можно
  дизассемблировать и патчить — мы не утверждаем обратного. [`EULA.md`](../EULA.md) прямо
  запрещает такие попытки договорно (не только технически).
- **Pro-модули физически в том же образе, всегда.** Включаются проверкой лицензии во время
  работы — отдельного «официального» бинарника для Pro не существует.
- **Формат обмена с сервером лицензий не публикуется.** Публично документировано, что именно
  передаётся и не передаётся (разделы 5.2–5.3 выше), — этого достаточно, чтобы оператор мог
  доверять поведению установки, не зная внутреннего устройства механизма.
- **Технические меры (закрытый бинарник, подписанные короткоживущие лизы, привязанные к
  установке, серверная детекция клонов) лишь повышают трудоёмкость** вмешательства, но не
  делают его невозможным. Формулировка «взлом невозможен» здесь и нигде в документации MGate
  не используется.
- **Проверка лицензии никогда не трогает содержимое почты** и не имеет функции удалённого
  отключения сервера.
