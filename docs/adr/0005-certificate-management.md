# 0005. Сертификаты владеет `mgate` (встроенный ACME) + Traefik file provider

Статус: Принято (реализовано) — встроенный ACME-клиент бэкенда (`mgate-acme`, `mgate-worker`) обеспечивает автоматический заказ и продление сертификатов (Let's Encrypt / ZeroSSL, HTTP-01 и DNS-01); поддерживается также загрузка собственных сертификатов через админку, см. [DEPLOYMENT.md](../DEPLOYMENT.md) §4

Дата: 2026-09-12

## Контекст

Нужен TLS не только для Traefik (HTTPS админки/веб-почты), но и для Postfix (STARTTLS
на 25/587, TLS wrapper на 465) и Dovecot (IMAPS/POP3S на 993/995, STARTTLS на 143/110)
— все на один и тот же FQDN (`MGATE_HOSTNAME`) плюс, потенциально, дополнительные домены
(MTA-STS, autoconfig/autodiscover поддомены). Traefik умеет сам получать
Let's Encrypt-сертификаты (встроенный ACME-провайдер), но тогда Postfix/Dovecot не имели
бы доступа к тем же файлам без дублирования логики выпуска, а кастомная загрузка
сертификата пользователем (возможность «SSL/TLS: загрузка кастомных») плохо ложится на
модель "Traefik сам всё решает".

## Решение

Выпуском, продлением и хранением сертификатов управляет **сам бэкенд `mgate`**
(встроенный ACME-клиент, HTTP-01 и DNS-01), а не Traefik. Результат
пишется в общий том `certs` (`/certs/live/<name>/{fullchain,privkey}.pem`,
`/certs/default/{fullchain,privkey}.pem` — сертификат для `MGATE_HOSTNAME`, используемый
как дефолт всеми сервисами). Traefik получает конфигурацию TLS через **file provider**:
`mgate` пишет `/etc/traefik/dynamic/10-certs.yml` в разделяемый том `proxy-dynamic`;
Traefik подхватывает изменения без перезапуска (встроенный hot-reload file provider).
Postfix и Dovecot читают файлы из `/certs/default` напрямую и перечитывают их по сигналу
от `mgate-agent`, который следит (`notify` fs watch) за этим путём и вызывает
`postfix reload` / `doveadm reload`. Entrypoint-скрипты Postfix/Dovecot генерируют
самоподписанный bootstrap-сертификат в `/certs/default`, если ACME ещё не успел
отработать — чтобы сервисы могли подняться и слушать TLS-порты сразу после старта.

## Альтернативы

- **Встроенный ACME-провайдер Traefik** (Traefik сам получает и хранит сертификаты):
  проще для одного HTTPS-сайта, но не даёт единого пути для TLS Postfix/Dovecot и не
  вписывается в загрузку пользователем собственного сертификата через админку (нужно
  API + БД для хранения метаданных о сертификате — загрузка через Traefik potentially
  требует дополнительного механизма конфигурации). Отклонено, чтобы иметь один код,
  управляющий жизненным циклом сертификата для всех потребителей.
- **cert-manager / отдельный ACME-клиент сторонней утилиты (`certbot`, `acme.sh`) в
  отдельном контейнере**: добавляет ещё один процесс/контейнер и требует своей
  интеграции с БД (для хранения метаданных, кастомных загруженных сертификатов,
  привязки к домену) — решили не вводить: логика выпуска встроена в бэкенд и
  может быть частью существующих `api`/`worker`, без отдельного контейнера.
- **Хранение приватных ключей только в БД (без файлов на диске)**: Postfix/Dovecot не
  умеют читать TLS-ключи из HTTP/SQL на лету — им нужны файлы на файловой системе;
  поэтому БД (метаданные, история, кастомные сертификаты) + файлы (`/certs`, для
  демонов) сосуществуют, БД как источник истины, файлы — как материализованное
  представление для демонов, которые не читают их из БД напрямую.

## Последствия

- Встроенный ACME-клиент бэкенда — единственный компонент, взаимодействующий с ACME CA;
  `worker` отвечает за продление, `api` — за интерактивную часть
  HTTP-01 challenge через `/.well-known/acme-challenge/`.
- Общий том `certs` должен быть смонтирован в `traefik`, `postfix`, `dovecot`,
  `api`/`worker` (владелец записи), что описано в `docs/ARCHITECTURE.md` §5 (тома).
- Постоянный процесс перечитывания сертификатов у Postfix/Dovecot реализован через
  `mgate-agent` (`notify` fs watch + reload) — не через полный рестарт контейнера, чтобы
  не рвать активные SMTP/IMAP-соединения при продлении сертификата.
- HTTP-01 требует, чтобы порт 80 был доступен снаружи именно на `api` (маршрут
  `/.well-known/acme-challenge/` в Traefik, см. `docs/ARCHITECTURE.md` §3) — DNS-01 остаётся
  единственным вариантом для инсталляций без публичного порта 80 или для
  wildcard-сертификатов; выбор провайдера DNS-01 (`MGATE_ACME_DNS_PROVIDER`) — открытый
  список провайдеров, реализуемый постепенно (`TODO(S1)`, начать минимум с одного
  провайдера, например Cloudflare, задокументировать остальные как план).
