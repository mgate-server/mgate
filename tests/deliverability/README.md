# Тест доставляемости (deliverability)

Цель: **10/10 на mail-tester.com** перед релизом.

## Как это проверяется руками (обязательный финальный шаг)

mail-tester.com не имеет открытого бесплатного API для программной проверки "с нуля" —
официальный способ: отправить письмо на одноразовый адрес `xxxxx@mail-tester.com` и открыть
отчёт по ссылке `https://www.mail-tester.com/xxxxx` в браузере. Поэтому `run_check.py` ниже
**не может** полностью автоматизировать получение итоговой оценки; он автоматизирует
подготовительный шаг (отправку письма через MGate) и печатает то, что можно проверить
программно локально (см. чек-лист), а итоговую оценку 10/10 фиксирует человек по ссылке
отчёта — это и есть ручной финальный шаг релизной проверки, не regression в CI.

## Чек-лист (то, что определяет оценку mail-tester)

Каждый пункт — что именно в MGate должно быть настроено правильно к моменту проверки:

- [ ] **SPF**: TXT-запись домена содержит корректный механизм (его генерирует MGate) и не
      превышает 10 DNS-lookups.
- [ ] **DKIM**: подпись присутствует, ключ ≥ 2048 бит, селектор совпадает с DNS TXT-записью
      (`docker/rspamd` и DNS-подсказки MGate).
- [ ] **DMARC**: TXT-запись существует, политика согласована с реальным поведением
      (как минимум `p=none` на старте, документировать переход на `p=quarantine`/`p=reject`
      в `docs/DNS.md`).
- [ ] **rDNS/PTR**: A-запись `MGATE_HOSTNAME` → IP, и PTR IP → тот же hostname (это со стороны
      хостинг-провайдера/сети, не MGate — `scripts/install.sh` уже печатает подсказку).
- [ ] **HELO/EHLO** совпадает с PTR/A (Postfix `myhostname`).
- [ ] Сервер не числится в основных DNSBL (Rspamd RBL-модуль) — а также сам IP
      "чистый" (вне контроля MGate, ответственность оператора при выборе IP/хостинга).
- [ ] Содержимое письма: корректные `Content-Type`/`charset`, plain-text альтернатива у HTML
      писем, нет "spam-словных" паттернов (это зона Webmail/шаблонов писем).
- [ ] TLS на всех этапах, где применимо (STARTTLS исходящий — если тестовое письмо шлётся через
      submission с последующей опциональной TLS-доставкой; сам mail-tester проверяет TLS
      входящего соединения к своему серверу, что зависит от `smtp_tls_security_level` в Postfix).

## Запуск подготовительного шага

```sh
python3 tests/deliverability/run_check.py --to xxxxx@mail-tester.com
# … затем открыть https://www.mail-tester.com/xxxxx и вручную зафиксировать оценку в
# docs/ROADMAP.md / релизном чек-листе.
```

`run_check.py` использует ту же отправку, что и `scripts/smoke-test.sh` (submission на 587 с
STARTTLS+AUTH, т.к. это ближе всего к тому, как реальный пользователь MGate отправляет письмо),
и дополнительно печатает конкретные проверяемые пункты выше как напоминание — без доступа к
отчёту mail-tester сам скрипт не может сказать "10/10", это не обман, а честное ограничение
внешнего сервиса без API.
