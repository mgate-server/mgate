# E2E-тесты MGate

Сквозные сценарии, проверяющие развёрнутый стек как единое целое (в отличие от юнит-тестов
внутри отдельных компонентов, которые проверяют их в изоляции). Запускаются против
уже поднятого стека (`make dev` или `make up`) — сами тесты ничего не поднимают и не собирают.

## Статус

Здесь раннер (`run.py`) и набор сценариев. Часть сценариев проверяет функциональность,
которая может быть ещё не реализована в развёрнутой версии или недоступна в данном стеке,
поэтому каждый сценарий обязан корректно определять состояние «функциональность недоступна» и
**пропускать себя** (`SKIP`), а не падать (`FAIL`) — падение зарезервировано за случаями, когда
функциональность заявлена реализованной, но ведёт себя не так, как описано в документации
(`docs/ARCHITECTURE.md`, `docs/CONFIGURATION.md`).

## Структура

```
tests/e2e/
├── README.md
├── run.py                 # раннер сценариев (stdlib only, без внешних зависимостей)
└── scenarios/
    ├── __init__.py
    ├── 01_admin_bootstrap.py   # mgate init создаёт суперадмина, /api/v1/auth/login работает
    ├── 02_domain_mailbox.py    # создание домена+ящика через admin API, DNS-подсказки
    ├── 03_mail_delivery.py     # SMTP→LMTP→Maildir, DKIM подпись, Rspamd-заголовки
    ├── 04_webmail_session.py   # логин в webmail, список папок, отправка письма
    ├── 05_account_selfservice.py  # профиль, квота, 2FA, app-пароли, автоответчик, сессии
    ├── 06_admin_licensing.py   # дашборд администратора, статус лицензии, домены/ящики
    └── 07_pro_module.py        # проверка ограничений Community/Pro на стороне сервера
```

## Запуск

```sh
make dev                 # поднять инфраструктуру (см. корневой Makefile)
python3 tests/e2e/run.py                      # все сценарии
python3 tests/e2e/run.py --only 03_mail_delivery   # один сценарий
```

Переменные окружения — те же, что у `scripts/smoke-test.sh` (`SMOKE_HOST`,
`SMOKE_TEST_DOMAIN`, `SMOKE_TEST_USER`, `SMOKE_TEST_PASSWORD`, а также
`MGATE_SMTP_PORT`/`MGATE_IMAPS_PORT` и прочие порты хоста из `.env`), плюс
`MGATE_API_BASE` (по умолчанию `http://127.0.0.1:8080`) для сценариев, обращающихся
к REST API.

`make dev` публикует `api` на `127.0.0.1:${MGATE_DEV_API_PORT:-8080}`, поэтому значение
по умолчанию подходит для dev-стека на той же машине (если порт изменён через
`MGATE_DEV_API_PORT` в `.env`, задайте `MGATE_API_BASE` явно). В production-стеке порт 8080
контейнера `api` наружу не публикуется (снаружи доступен только Traefik) — задайте
`MGATE_API_BASE` явно, например `https://<MGATE_HOSTNAME>` через Traefik. Если по адресу отвечает чужой сервис,
сценарий 01 завершается со статусом `SKIP`, а не `FAIL`.

## Соглашение о статусах сценария

Каждый сценарий — функция `run() -> ScenarioResult`, `ScenarioResult.status` одно из:
`OK` (прошёл), `SKIP` (предпосылка отсутствует — сценарий обязан указать, что именно недоступно), `FAIL` (поведение разошлось с контрактом). Раннер завершается
ненулевым кодом только если есть хотя бы один `FAIL`.
