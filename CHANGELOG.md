# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

Проект использует календарное версионирование **CalVer `YYYY.M.N`** (год, месяц без ведущего
нуля, порядковый номер сборки внутри месяца с 1; например, `2026.10.1`) — это корректная
SemVer-версия. Первый публичный релиз — **`2026.10.1`**.

## [2026.10.1] - 2026-10-08

Первый публичный релиз.

### Added
- Почтовое ядро: Postfix, Dovecot 2.4 (IMAP/POP3/LMTP/ManageSieve), Rspamd (антиспам,
  DKIM/SPF/DMARC/ARC), ClamAV, локальный DNSSEC-резолвер Unbound.
- TLS: по умолчанию отдаётся самоподписанный сертификат; собственный сертификат (цепочка и
  ключ в PEM) загружается и заменяется вручную в админке («Сертификаты»), причина отказа при
  загрузке показывается в окне. Автоматический выпуск Let's Encrypt — в разработке (см. Known
  limitations).
- IMAP-миграция: перенос ящиков с Яндекс 360, Google Workspace, Mail.ru и любых IMAP-серверов
  — пакетно администратором («Импорт и миграция») и самостоятельно пользователем; выполняется в
  фоне средствами Dovecot.
- Единый веб-интерфейс (SPA): панель администратора, личный кабинет пользователя и веб-почта
  (`/mail`); мастер DNS с проверкой записей по кнопке «Проверить DNS», очередь писем, живые
  логи, статистика.
- Веб-почта (`/mail`) поверх IMAP/SMTP самого сервера: папки (создание, переименование,
  удаление, перемещение писем, «в спам»), списки с поиском и цепочками, чтение с безопасным
  показом HTML (внешние изображения скрыты до нажатия), черновики с автосохранением, ответ и
  пересылка, вложения, контакты (импорт и экспорт CSV/vCard), подписи, настройки, обновления в
  реальном времени. Доступ — только по сессии почтового ящика; веб-почта работает от имени
  пользователя через короткоживущие учётные данные и внутренние порты, которые не публикуются.
- Безопасность входа: ограничение подбора пароля для веб-входа, смены пароля и
  IMAP/POP3/SMTP (общий счётчик, без возможности заблокировать пользователю вход с его обычного
  адреса); cookie сессии с префиксом `__Host-` и защитой CSRF; отключение ящика, домена или
  администратора сразу завершает их сессии, включая открытые IMAP-соединения; смена пароля
  действует немедленно. Закрытые ключи DKIM хранятся в базе в зашифрованном виде.
- Домены и доступ: администраторы доменов (Domain Admin) и квоты домена (число ящиков, объём)
  входят в Community.
- DKIM: ключ RSA-2048 генерируется при создании домена; ротация выполняется вручную кнопкой
  «Ротировать DKIM» (см. [`docs/OPERATIONS.md`](docs/OPERATIONS.md)).
- DMARC: XML-отчёты загружаются в панель вручную (автоматического приёма нет), сводка за 7 дней;
  полные IP источников, история до 90 дней и скачивание исходных XML — в Pro (DMARC
  Intelligence, входит в любую Pro-лицензию, отдельного переключателя нет). Имена хостов и география источников не определяются.
- Разовая «Автонастройка» DNS (кнопка в мастере домена): Cloudflare и Selectel; доступна во
  всех редакциях. Фоновая сверка записей (Pro) — в разработке.
- Редакции Community (1 домен, бесплатно) и Pro (подписка); активация по ссылке или коду —
  см. [`docs/LICENSING.md`](docs/LICENSING.md). Работающие Pro-модули: неограниченное число
  доменов, white-label (название продукта и логотип в шапке интерфейса и заголовке вкладки;
  favicon, акцентный цвет, ссылка поддержки и футер сохраняются, но пока не отображаются),
  DMARC Intelligence. Состав редакций и планы — [`docs/ROADMAP.md`](docs/ROADMAP.md).
- Первый администратор: если `MGATE_ADMIN_PASSWORD` пуст, пароль генерируется и один раз
  выводится в лог сервиса `migrate`; сброс — `docker compose exec api mgate admin reset-password
  <email>`.
- Развёртывание: Docker Compose, Helm-чарт (`deploy/helm/mgate`), резервное копирование
  (restic + pg_dump), сетевой экран хоста (nftables, профиль `firewall`).
- Образы в GitHub Container Registry: `ghcr.io/mgate-server/*` (`mgate`, `mgate-agent`, `web`,
  `postfix`, `dovecot`, `rspamd`, `unbound`, `traefik`, `backup`, `firewall`); публичные,
  скачиваются без авторизации; архитектура — `linux/amd64`. Все образы содержат стандартные
  OCI-метки (`org.opencontainers.image.*`).
- Календарное версионирование CalVer `YYYY.M.N`: единая версия для всех образов, Helm-чарта и
  backend. Теги образов: `2026.10.1` (неизменяемый), `2026.10` (плавающий — последняя сборка
  месяца), `latest`; git-теги — `v2026.10.1`. Файл `VERSION` в корне репозитория.
- Unbound: каталог расширений `/etc/unbound/conf.d/*.conf` — например, чтобы направить запросы
  приватной зоны на внутренний резолвер (см. `docker/unbound/README.md`).
- Ссылки на тарифы и портал вендора в интерфейсе настраиваются переменными
  `MGATE_PRICING_URL` и `MGATE_VENDOR_PORTAL_URL` (по умолчанию пусто — ссылки скрыты).
- Прокси для исходящих соединений (`HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY` в `.env`) передаются
  сервисам `api` и `worker`; `make init` сохраняет в `.env` собственные переменные оператора.
- Документация: установка, конфигурация, DNS, резервное копирование, эксплуатация, версии и
  обновление (см. [`docs/README.md`](docs/README.md)).

### Known limitations
- **Двухфакторная аутентификация (TOTP) в разработке**: вход выполняется только по паролю,
  одноразовый код не запрашивается и не проверяется; подключение 2FA в личном кабинете и
  принудительная 2FA для ящиков отключены в интерфейсе.
- **Автоматический выпуск и продление сертификатов (Let's Encrypt / ZeroSSL) в разработке**:
  по умолчанию отдаётся самоподписанный сертификат, собственный сертификат загружается и
  продлевается вручную; переменные `MGATE_ACME_*` ничего не выпускают.
- Pro-модули **в разработке** (API отвечает `501 not_implemented`, в интерфейсе помечены «В
  разработке»): Backup Center, Advanced Dashboard, расширенная мультиарендность (Multi-tenant
  RBAC), фоновая сверка DNS-Автопилота, приоритетные обновления.
- Отказоустойчивость: Dovecot — только active/passive (один экземпляр на хранилище `vmail`;
  Director в Dovecot 2.4 CE отсутствует); Valkey/Redis — один endpoint, Redis Cluster и
  Sentinel не поддерживаются. См. [`docs/HA.md`](docs/HA.md).
- Автонастройка DNS поддерживает только Cloudflare и Selectel.
- Политика MTA-STS публикуется в режиме `testing`; проверка DNS выполняется по запросу, без
  фоновой задачи; ротация DKIM — ручная.
- SRS для пересылок и предупреждения о приближении к квоте ящика не реализованы.
- Веб-почта: по умолчанию один экземпляр сервиса; для нескольких реплик в Kubernetes нужна
  привязка сессии на Ingress (загружаемые вложения хранятся локально в реплике). Для писем
  больше `MGATE_WEBMAIL_MAX_RENDER_BYTES` показываются только заголовки, скачивание — 413.
